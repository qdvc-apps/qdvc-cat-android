### What's in this build

**Core viewer** — opens a plaintext file from an "Open with" intent and renders it in a monospace font with line numbers, adjustable text size, and optional word wrap. Reading is defensive (8 MB cap, binary sniff, graceful errors) and off the main thread.

**"Open with" integration** — the manifest registers three VIEW intent-filters: `text/*`, a set of structured `application/*` MIME types, and an extension-based fallback for browsers that report `octet-stream`. So QDVC Cat shows up in the file-browser share/open menu for all the listed formats.

**Modular syntax highlighting** — a declarative, regex-rule grammar engine in the Monarch/Prism style (the pragmatic middle ground between hardcoding and a full TextMate/oniguruma engine). Grammars emit *semantic scopes*, and themes map scopes to colours, so one small palette drives every language. Adding a language = one grammar file + one registry line. Grammars written and **tested** for JSON, YAML, CSV, TSV, SQL, Python, CSS, and Markdown (with YAML frontmatter). Plain `.txt` gets no highlighting, as requested.

**Themes** — all eight palettes carried over from `qdvc-markdown-notebook-android` (Regular Light/Dark, Pure Black, Everforest Light/Dark, Rosé Pine / Moon / Dawn). Since those only carried ~11 Material roles — not enough for real highlighting — I dug into `vibe-coding/2026-07-18-claude.md`, recovered the upstream accent sources (sainnhe's Everforest *medium* variant and the official Rosé Pine palette), and extended each theme JSON with a full `syntax` block.

**Settings page** — light/dark mode defaulting to "Follow system", per-mode theme pickers with colour swatches, font-size slider, and word-wrap toggle.

**Verification** — I compiled the entire highlighting core with kotlinc, ran a test harness over sample files for all 8 languages (confirming multi-line constructs, frontmatter, and column alternation work), validated all 8 theme JSONs, and ran a performance test: a 100k-line file tokenises 200 on-screen lines in ~12ms thanks to the lazy per-line design. The Compose/Android UI layer is written to the same conventions as the reference app but couldn't be compiled here (no Android SDK, and `dl.google.com` is outside the sandbox's allowed domains) — so it hasn't been through a full Gradle build.
